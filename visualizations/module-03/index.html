Part 2 · From Prompting to Context Engineering

A perfect prompt can still fail. When it does, the cause is usually the information around it: missing, wrong or too much context.

Model guesses.

What you see

Invents a method name, a config key, or a library your repo doesn't use.

The fix

Add the right files, docs or spec.

Model follows stale info.

What you see

Copies an old pattern, a deprecated API, or an outdated decision from earlier in the chat.

The fix

Remove it; refresh from the source of truth.

Model loses the thread.

What you see

Ignores your constraint because it is buried under 40 files and a long history.

The fix

Cut to the smallest set that still answers.

Try it · diagnose the symptom

The shift: prompt engineering optimises the words of the request. Context engineering optimises the whole set of tokens the model sees when it answers. Same model, very different results.

Your prompt is one small slice of what the model actually reads. Select a slice of a Copilot chat request (illustrative proportions).

Part 4 · Failure Modes & Token Discipline

More context is not better context. Know the symptoms so you can diagnose a bad answer quickly.

1 · Poisoning

A wrong fact or hallucination enters the window and gets reused.

Start fresh; correct at the source.

2 · Distraction

So much history that the model repeats it instead of reasoning.

Compress; new chat.

3 · Confusion

Irrelevant files or tools pull the answer off target.

Select fewer, sharper sources.

4 · Clash

Two sources disagree (old spec vs new code); the model blends them.

Remove or reconcile one.

Models use information at the start and end of the input best; facts buried in the middle are used less reliably (Liu et al., TACL, 2024). The bars are the deck's illustrative shape of recall by position, not measured data.

Beyond pre-loading: agents can retrieve just in time, so the window holds only what is needed right now.

Pre-loaded (up front)

You decide in advance

  • Attach files and docs
  • Always-on instructions
  • Good: predictable, fast
  • Risk: bloat, stale, wasted

Just-in-time (on demand)

Agent searches, reads, calls tools

  • Search → open file → read range
  • MCP tools fetch live data
  • Good: small window, fresh
  • Risk: more steps, needs good tools

Try it · build the hybrid: pre-load or on demand?

Three agentic context patterns

Skills — progressive disclosure

Only name + description load first; full instructions load when the task matches.

Memory & notes files

The agent writes plan.md or notes.md outside the window and reads them back later.

MCP tools

Live data (issues, docs, DB) comes in as a small tool result, not a pasted dump.

Best practice: hybrid wins — pre-load the small stable core (instructions, spec); let the agent retrieve the rest on demand.
