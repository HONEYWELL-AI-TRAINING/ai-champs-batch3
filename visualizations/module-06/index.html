Module 06: Test Strategy & Validation

AI can write code and tests faster than you can read them. Build the testing stack that proves the code matches the spec — from unit tests and test doubles to integration, contract and regression checks — then break something on purpose to prove it works.

Interactive Concept Guide
1.5 hours Concepts + defect-injection lab Copilot + your test framework

Your Map for the 90 Minutes

Build the stack from the bottom up, then prove it works by breaking something on purpose. Select a stop to jump to its first card.

Why this matters: the faster AI writes code, the more your safety depends on tests you trust. Specs from Modules 04–05 become tests here (acceptance criteria are the source of every test; characterization and regression tests protect brownfield change), and tests become the gate in M08's PR automation, which checks test evidence against the spec. Defect-catch and rework data later feed M11 (observability and ROI). One running example throughout: the refund feature.

      Part 3 · Integration, API & Database Validation
      

        
      
            
      
                
            
      
            
      
                
      
                    
      Keep the parts you own real. Replace only what you cannot control or what is slow.
      
                    
      
                        
                    
      
                    
      
                        
      IsolateEach test seeds its own data and cleans up; no test depends on another
      
                        
      Disposable databaseA real engine in a container, or an in-memory mode your team trusts
      
                        
      Test failure pathsMake the stub time out or return 500 and see what the service does
      
                    
      

                    
      Try it · make the payment stub misbehave
      
                    
      
                        
                        
                        
                    
      
                    
      

                    
      Sort it · what can a unit test with doubles NOT catch?
      
                    
      
                    
      
                    
      Best practice: integration tests prove the wiring that unit tests with doubles cannot: mappings, queries, transactions, configuration.
      
                
      
            
      
        
      

        
      
            
      
                
            
      
            
      
                
      
                    
      A good API test asserts what came back and what did — or did not — change underneath. Choose your assertions, then run the test against a good and a buggy service.

        API checks
        • Status codes for success and each failure
        • Response matches the schema
        • Error shape is stable and documented
        • Auth: allowed and forbidden callers
        
                        
        Database checks
        • State after success is exactly right
        • Failure leaves state untouched (rollback)
        • Constraints and uniqueness hold
        • Migrations apply to a clean database
        
                    
        
                    
        Best practice: for every failing request, also assert nothing changed. Half-applied writes are the bugs that cost the most to find later.

        Part 4 · Negative, Contract & Regression
        

        
        
            
        
                
            
        
            
        
                
        
                    
        AI generates happy paths readily. You have to ask for the rest — one prompt per row of this checklist.
        
                    
        
                        
        Invalid inputNull, empty, wrong type, too long, malformed
        
                        
        BoundariesExactly at, one below, one above every limit
        
                        
        Not allowedUnauthenticated, wrong role, someone else's data
        
                        
        Dependency failsTimeout, 500, slow response, empty reply
        
                        
        Repeat and overlapDuplicate request, retry, two at once
        
                        
        Wrong stateRefund an unpaid or already-refunded order
