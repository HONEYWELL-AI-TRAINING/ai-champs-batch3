Module 08: PR Automation, Quality Gates & LLM-as-Judge

Make pull-request review faster and more consistent without lowering the bar: AI review with evidence, quality gates in CI, and an LLM judge you can calibrate and trust, with a human always closing the loop.

Interactive Concept Guide
1 hour Concepts · 1 lab Copilot code review + CI

Your Map for the Hour

From why review needs help, to gates, to judging the reviewer itself. Select a stop to jump to its first card.

Why this matters: AI raises the volume of code faster than humans can read it. Review has to get smarter, not just faster. Agents now write and review code; this module makes sure someone checks the checkers. The spec from Modules 04–05 is what review checks the change against, test evidence and regression risk come from Module 06's strategy, MCP tools (Module 07) feed review agents under the same governance, and judge scores and gate results become quality metrics in Module 11.

Part 1 · AI-Assisted PR Review

Each stage removes a kind of problem so the human reviewer spends time on judgement. Select a stage.

DeterministicProbabilisticAccountable

Try it · what actually blocks the merge?

Principle: AI review and judges advise; they do not own the decision. Merge approval stays with a named human, and required CI checks, not AI comments, are what block a merge.

Six dimensions — the first two are the ones generic review tools miss.

Specification complianceDoes the change meet each acceptance criterion in spec.md?
★ generic tools miss this
Test evidenceDo tests exist for the new behaviour, and do they actually assert it?
★ generic tools miss this
Coding and design standardsNaming, layering, patterns your team agreed — written down.
Security checksInput handling, secrets, authorisation, risky dependencies.
Regression riskWhat else calls this code? What existing behaviour could change?
MaintainabilityComplexity, duplication, readability for the next person.

Real-world use case · the change passes CI and looks tidy, but silently drops an acceptance criterion

Illustrative change: AC-3 says reject quantity ≤ 0. The new code path accepts 0. Run each reviewer on it.

    Only a spec-aware review catches that; a linter never will.

    Sort it · which dimension does each finding belong to?

    A comment you cannot verify costs more reviewer time than it saves.

    ✗ Weak comment
    “This might have security issues. Consider improving error handling.”
    No location, no evidence, no action, no confidence.
    ✓ Evidence-based (illustrative)
    “OrderService.cs L42: AC-3 requires rejecting quantity ≤ 0, but this path accepts 0. No test covers it. Suggest a guard and a boundary test. Confidence: high.”

        Part 4 · LLM-as-Judge
        

        
        
            
        
                
            
        
            
        
                
        
                    
        Use it when “is this good?” needs judgement that a rule or a test cannot express.
        
                    
        
                        
        Inputs
        Spec, output, rubric
        Task or spec, the output under review, and the rubric
        
                        →
                        
        Judge model
        Applies the rubric
        Criterion by criterion
        
                        →
                        
        Score + rationale
        With cited evidence
        Per-criterion score
        
                        →
                        
        Action
        Pass, advise or escalate
        To a human where needed
        
                    
        
                    
        Used in code review to judge…
        
                    
        
                        
        The PR against the specDoes the PR meet the spec?
        
                        
        The AI reviewerIs the AI reviewer's comment correct and useful?
        
                        
        The descriptionIs the PR description accurate?
        
                        
        The testsIs the generated test meaningful?
        
                    
        
                    
        Remember: a judge is another model. It can be wrong, biased or inconsistent, so it is measured and calibrated like any other check — which is what the next cards cover.
        

                    
        Sort it · a rule or test, or a judge?
        
                    
        
                    
        
                
        
            
        
        
        

        
        
            
        
                
            
        
            
        
                
        
                    
        Vague rubrics give vague scores. Describe what each score level looks like.
        
                    
        
                        Anchored rubric
                        
        CriterionScore 1Score 3Score 5
        
                        
                            
        Spec complianceMisses a stated criterionMeets most; gaps unstatedEvery AC met, with evidence
        
                            
        Test evidenceNo tests for new behaviourTests exist; weak assertionsTests assert each AC and edge
        
                            
        Risk awarenessIgnores callers and rollbackMentions risk genericallyNames callers, impact, rollback
        
                            
        Comment qualityVague, no locationLocated but no fixLocated, evidenced, actionable
        
                                
                    
        
                    
        
                        
        Score + one-line quoteAsk for a score and a one-line evidence quote per criterion
        
                        
        Small discrete scaleUse something like 1–5, not free text
        
                        
        ExamplesInclude one good and one bad example per criterion
