Part 2 · Authoring a Grounded Agent

Try it · configure the agent, then ask it two things

Rule: out-of-the-box agents do not take actions. A custom agent can only act through the skills you give it — which is also your first safety control.

Specific instructions beat clever ones. Say what to do, for whom, and what to avoid.

✗ Vague
“Help with project status. Be accurate and professional.”
No audience, no sources, no format, no limits.
✓ Specific (illustrative)
“You are the Release Status Agent for programme leads. Using only the Release space, list open blockers per release as a table with owner and link. If a fact is not in the space, say so — do not guess.”

More autonomy runs left to right.

        Studio is the fast path. Hand over when the job outgrows what a studio should carry.
        
                    
        
                        
        Stay in Studio when…
        • The job lives in Jira and Confluence data
        • A person reviews the output
        • Rules fit triggers, conditions and a few actions
        
                        
        Hand to engineering when…
        • It needs custom code, tests or other systems
        • It must run at scale or with strict reliability
        • It needs retrieval or tools beyond the studio
