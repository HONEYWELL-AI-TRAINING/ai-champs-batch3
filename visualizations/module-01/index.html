Champions turn individual AI skill into team capability — and prove it with evidence. The role has four layers, each building on the last.

01

Practitioner

Uses Copilot Enterprise at power-user level: agent mode, custom instructions, skills, specs and MCP tools.

Uses it well

Makes it repeatable

Guardian

Holds the line on quality gates, spec compliance, security, governance and human review.

Keeps it safe
04

Multiplier & Measurer

Coaches the team, tracks baseline-to-ROI evidence and owns the adoption roadmap.

Spreads & proves it
The Champion's job: operationalise judgement, not add caution. You already know how to engineer — the programme makes good AI-assisted practice repeatable, governed and measurable across your team.

Part 2 · Climbing the Ladder, Rung by Rung

GenAI sits inside deep learning, inside machine learning, inside AI. What changes when a model generates rather than labels is what comes out of it.

Try it · same model box, different job

Learns boundaries → picks a label.

Sensor reading→ Model→ FaultNo fault

The output is one of a fixed set of labels. Nothing new is created.

Learns patterns → produces new content.

Prompt + context→ Model→ CodeTestsSpecsDocs

The output is new, open-ended content — which is why it needs checking.

In this programme: GenAI means LLMs generating code, tests, specs and reviews — output that must be verified like any colleague's first draft.

One token at a time, the model picks a likely continuation — then repeats. It has seen this pattern in vast amounts of code and text.

Implication: fluent is not the same as correct. Output is probable, not verified — which is why specs, tests and review sit at the core of this programme.

Models don't read words or lines; they read tokens. Every limit and every bill is counted in them.

CODE def·get_zone_temp(self,·zone_id): 10 tokens

    An agent is an LLM that pursues a goal over many steps — using tools, checking results, iterating.

    LLM

    Answers one question from what's in the window.

    Assistant

    Answers inside your IDE, grounded in your open code.

    Agent

    Takes a goal, plans steps, calls tools, verifies, repeats.

    Each step adds autonomy — and the need for guardrails.

    Part 3 · Where We Start

    Walk the lifecycle left to right and locate the friction on your team. Each stage has a typical "today" and an AI-assisted, spec-led "target".

    ✗ Today

    • Tickets and prose translate loosely into implementation tasks; prompt-only results vary by person.
    • Requirements arrive as tickets and prose.

    ✓ Target

    • Spec with acceptance criteria drives plan & tasks.

    ✗ Today

    • In brownfield code, AI-suggested changes can bypass existing patterns, contracts and extension points.

    ✓ Target

    • Brownfield lane: understand the repo, analyse impact, preserve patterns.

    ✗ Today

    • Repetitive coding, boilerplate and docs slow delivery; context is assembled ad hoc each time.
    • Each engineer prompts ad hoc, from scratch.

    ✓ Target

    • Shared instructions, skills and engineered context.

    ✗ Today

    • Test creation is manual and inconsistent; hard to show acceptance criteria are actually covered.
    • Tests written manually after the code.

    ✓ Target

    • Test strategy derived from the spec; mocks & stubs.

    ✗ Today

    • Review bottlenecks; spec compliance and regression risk are checked by eye, if at all.
    • PRs wait in a review queue.

    ✓ Target

    • AI review + LLM-as-Judge, then human approval.

    ✗ Today

    • Little visibility into AI usage, quality, failure patterns, token spend or ROI.
    • AI usage and token cost are invisible.

    ✓ Target

    • Traced usage; cost per accepted output tracked.
